Guida all'app eemkit

Come usare l'applicazione desktop di eemkit per passare dai file CSV del Cary Eclipse e del Cary 60 a EEM corretti, indici di fluorescenza, metriche CDOM, un modello PARAFAC validato e il confronto tra fiumi, siti e date.

eemkit, versione di sviluppo (novembre 2026) · app in PySide6 · schermate fatte sui dati dell'Ombrone 2024 (Polvani et al. 2026, doi:10.1016/j.envpol.2026.127858)

L'app è un'interfaccia sopra la libreria eemkit: non fa calcoli suoi. Ogni pulsante chiama le stesse funzioni usate dagli script dell'Ombrone (eemkit.pipeline), e sui dati reali produce gli stessi risultati: il modello a 3 componenti ottenuto nell'app ha varianza spiegata 99,017 %, core consistency 85,5 % e split-half 0,9915, come nell'analisi fatta con gli script.

Le etichette dell'app sono in inglese. In questa guida le trovi scritte così: Apply corrections, cioè esattamente come appaiono sullo schermo.

Avviare l'app

Da Python

Serve Python 3.11 o più recente (su Windows, nell'installazione spunta Add python.exe to PATH). Poi, in un terminale (su Windows: PowerShell dal menu Start):

python -m pip install "eemkit[gui] @ https://github.com/LowCostSensor/eemkit/archive/refs/heads/main.zip"
python -m eemkit.gui

Il primo comando installa eemkit da GitHub (non è ancora su PyPI); la parte [gui] serve per l'app. Il secondo la avvia. Per aprire direttamente un progetto, passa il file come argomento:

python -m eemkit.gui percorso\del\progetto.toml

Aggiornare un'installazione già fatta

Finché il numero di versione non cambia, --upgrade non basta: serve reinstallare eemkit (le altre librerie restano):

python -m pip install --force-reinstall --no-deps "eemkit @ https://github.com/LowCostSensor/eemkit/archive/refs/heads/main.zip"

Il progetto dell'Ombrone, già pronto

Ho preparato ombrone-fdom/config/ombrone_project.toml: contiene i parametri confermati in config/processing.toml, la cartella dei dati data/raw (la copia dei CSV nel repository), la tabella config/pairing.csv e una cartella di uscita outputs/gui, tutti relativi al file di progetto. Aprilo con File → Open project… e passa subito al punto 3 del flusso.

Tieni la tabella com'è

config/pairing.csv contiene 22 righe escluse di proposito (per esempio FARMA 62 e FARMA DICEMBRE). Se per errore le includi tutte, riporta il file alla versione del repository con git checkout -- config/pairing.csv.

Eseguibile Windows (senza Python)

Ogni release avrà una versione autonoma compressa (circa 160 MB una volta estratta): basta estrarla e avviare eemkit.exe.

Se l'eseguibile si chiude subito

Il motivo è scritto in eemkit-crash.log nella cartella temporanea (%TEMP%).

Cinque cose da sapere

  1. Il progetto è un file di impostazioni. Salvare il progetto scrive un file .toml con tutti i parametri e i percorsi, nello stesso formato di processing.toml. Non salva i risultati: quelli si ricalcolano dal file, oppure si esportano dal passo 6, Export.
  2. La cartella dei dati è in sola lettura. L'app non scrive, non rinomina e non sposta nulla lì dentro, e rifiuta di salvarci progetto, tabella o risultati.
  3. Nessun abbinamento silenzioso. L'app usa solo le righe della tabella degli abbinamenti con include = yes. Le righe proposte automaticamente partono sempre escluse.
  4. I risultati non restano mai superati. Se cambi un parametro, l'app scarta i risultati che ne dipendevano: per esempio, cambiare la larghezza di una banda di scattering cancella i modelli PARAFAC già calcolati, che vanno ricalcolati.
  5. I calcoli lunghi girano in background. In basso compaiono una barra di avanzamento e il pulsante Cancel; l'annullamento ha effetto alla fine del modello in corso. Se un calcolo produce avvisi (per esempio un modello che non converge), compare il pulsante ⚠ N warnings: cliccalo e leggili prima di usare i risultati.

Il flusso di lavoro

I passi sono elencati nella barra a sinistra, nell'ordine dell'analisi; un ✓ segna quelli completati e sotto l'elenco c'è un riepilogo del progetto. Ogni passo usa il risultato del precedente. In ogni pagina il pulsante colorato è l'azione principale.

  1. Scegli le cartelle (passo 1): dati, tabella degli abbinamenti, uscita. Oppure apri un progetto esistente.
  2. Prepara la tabella degli abbinamenti (passo 1): aprila se esiste già; altrimenti scansiona la cartella, genera la bozza, controlla e includi le righe.
  3. Carica i dati con 3. Check and load data.
  4. Applica le correzioni (passo 2) e controlla qualche campione nell'anteprima.
  5. Calcola indici e metriche CDOM (passo 3).
  6. Esplora i modelli PARAFAC (passo 4), guarda la diagnostica e i campioni anomali, poi calcola il modello finale.
  7. Confronta fiumi, siti e date (passo 5), se ti serve.
  8. Esporta (passo 6) e salva il progetto.

1 · Progetto e abbinamento

Questa pagina decide quali file vengono letti e come sono abbinati tra loro.

I tre percorsi

  • Data folder: la cartella con i CSV degli strumenti (per l'Ombrone, data/raw nel repository ombrone-fdom).
  • Pairing table: il file CSV con gli abbinamenti. Open… ne apre uno esistente.
  • Output folder: dove il passo 6 scrive i risultati. Non può stare dentro la cartella dei dati.

Come viene proposta la bozza

  • Un file è considerato un bianco se il nome del campione o del file contiene blank, bianc, milli-q, MQ o ultrapure.
  • Assorbanza: il file di assorbanza con lo stesso nome del campione (ignorando maiuscole, spazi, _, - e .), preferendo quello nella stessa cartella. Se ce ne sono zero o più di uno, la cella resta vuota.
  • Bianco EEM e bianco di assorbanza: l'unico bianco nella stessa cartella. Se ce ne sono due, non sceglie.
  • Ogni scelta, o il motivo per cui non è stata fatta, è scritta nella colonna pairing_notes.
Per l'Ombrone

Non usare la bozza: la tua config/pairing.csv è già curata a mano (esclusioni di FARMA 62, FARMA DICEMBRE, FARMA 1 e 2 comprese). La bozza serve per un dataset nuovo.

Leggere e modificare la tabella

  • Colori delle righe: giallo = proposta automatica non ancora controllata; grigio = esclusa (non verrà letta); bianco = inclusa.
  • Doppio clic su una cella per modificarla. Nelle colonne dei file (eem_file, eem_blank_file, abs_file, abs_blank_file) si apre un elenco con i file del tipo giusto trovati dalla scansione.
  • La casella Filter rows… filtra su tutte le colonne (per esempio Merse_2024-07). Un clic sull'intestazione ordina per quella colonna.
  • Le colonne in più (fiume, campagna, sito, replicato, note…) diventano metadati dei campioni: le ritrovi negli indici e nei raggruppamenti.

2 · Correzioni

A sinistra i parametri, a destra l'anteprima. L'ordine dei passaggi è fisso: correzione spettrale dello strumento (facoltativa), bianco dell'assorbanza, effetto filtro interno, sottrazione del bianco, unità Raman, scattering, ritaglio.

Valori predefiniti

Per un progetto nuovo le bande di scattering partono da 10 nm, il valore predefinito di eemR e staRdom. È un punto di partenza generico: controllalo sui bianchi nell'anteprima prima di confermarlo.

Correzione spettrale dello strumento

Lampada, monocromatori e rivelatore non rispondono allo stesso modo a tutte le lunghezze d'onda. Se il Cary Eclipse misura con Corrected spectra OFF, come nei dati dell'Ombrone, gli EEM contengono questa risposta: le unità Raman restano coerenti tra i tuoi campioni, ma indici come il FI non sono confrontabili con quelli di altri strumenti (Cory et al. 2010).

  • Excitation file e Emission file: Choose… sceglie il file, Clear lo toglie. Servono tutti e due, oppure nessuno.
  • Formato: due colonne, lunghezza d'onda (nm) e fattore; righe di intestazione e separatori , ; tab o spazio vanno bene. I fattori devono coprire tutto l'intervallo di eccitazione ed emissione degli EEM ed essere positivi.
  • Appena scelto, il file viene letto e sotto compaiono numero di valori, intervallo e minimo/massimo dei fattori: così vedi subito se è il file giusto.
  • Files contain: correction factors (multiply) se il file contiene fattori di correzione (gli EEM vengono moltiplicati); instrument response (divide) se contiene la risposta dello strumento, per esempio uno spettro di riferimento (gli EEM vengono divisi).
  • La correzione si applica per prima, ai campioni e ai bianchi. Nel menu Step dell'anteprima, Spectral correction factors mostra i fattori effettivamente applicati; il riepilogo sotto il grafico riporta lo stato della correzione.
  • I dati registrati con Corrected spectra ON vengono rifiutati, così la correzione non si applica mai due volte.
Da dove vengono i fattori

eemkit non contiene fattori di correzione: sono propri di ogni strumento e vanno misurati, per esempio con standard di riferimento certificati, oppure forniti dal servizio tecnico dello strumento. Per l'Ombrone non ne abbiamo, quindi la correzione resta vuota.

Applicare e controllare

  • Apply corrections salva i parametri nel progetto ed esegue la catena. Sull'Ombrone richiede circa un secondo.
  • Sample sceglie il campione, Step il passaggio: Raw sample, Raw blank, After inner filter, blank, Raman units, Corrected (scatter removed, cropped), Spectral correction factors.
  • Nei passaggi prima della rimozione dello scattering la scala dei colori è limitata al massimo della fluorescenza; il titolo lo segnala.
  • Sotto il grafico, un riepilogo: stato della correzione spettrale, fattore di filtro interno su tutte le celle (mediana e massimo), area Raman dei bianchi con il suo CV, griglia finale e percentuale di celle mancanti. Sull'Ombrone: fattore massimo 1,39, CV dell'area Raman 3,1 %, 13,6 % di celle mancanti.
  • Con il mouse sul grafico puoi zoomare e spostarti con la barra degli strumenti di matplotlib; l'icona del dischetto salva l'immagine.

3 · Indici e CDOM

FI (Cory & McKnight 2005), HIX (Ohno 2002), BIX (Huguet et al. 2009) e i picchi di Coble (1996), calcolati sugli EEM in unità Raman, prima della rimozione dello scattering; nella stessa tabella, le metriche CDOM ricavate dagli spettri di assorbanza.

  • Excitations off the grid: come trattare le eccitazioni non misurate (254, 275 e 312 nm su una griglia a passi di 10 nm). linear interpola tra le due scansioni vicine; nearest usa la più vicina; exact rifiuta.
  • BIX denominator emission: emissione al denominatore del BIX (430 nm in Huguet et al. 2009).
  • Compute indices calcola la tabella (indici e metriche CDOM); Save table… la salva in CSV.
  • Il grafico si regola con Show (quale indice), along (asse x, per esempio campaign) e grouped by (per esempio river). I gruppi possono essere al massimo 8, uno per colore.
FI

Senza correzione spettrale dello strumento, il FI vale circa 2 ed è confrontabile solo con misure fatte sullo stesso fluorimetro.

  • Compute CDOM metrics from the absorbance spectra: le calcola insieme agli indici. Il cammino ottico della cuvetta è quello del passo 2.
  • Baseline: a ogni spettro si sottrae la sua assorbanza media fra 680 e 700 nm, dove il CDOM non assorbe (Green & Blough 1994; Helms et al. 2008). Nei dati dell'Ombrone serve: sopra 350 nm il segnale è dello stesso ordine degli scostamenti della linea di base (±0,006).
  • Minimum R² of slope fits (0,95): sotto questo valore la pendenza non viene riportata. È una soglia di qualità di eemkit, non un valore della letteratura: dichiarala.
  • DOC column (mg/L): una colonna della tabella degli abbinamenti con il DOC; serve per SUVA254.
  • Quando il segnale non basta (assorbanza ≤ 0 o fit scadente) la cella resta vuota e il motivo è nella colonna cdom_notes. Sull'Ombrone, con la cuvetta da 1 cm, SR c'è per 165 campioni su 205.

4 · PARAFAC

A sinistra le impostazioni, a destra quattro viste dei risultati. Si lavora in due tempi: prima i modelli esplorativi per scegliere il numero di componenti, poi il modello finale.

Impostazioni dei modelli esplorativi

  • Components da … a …: l'intervallo di componenti da provare.
  • Random starts: inizializzazioni casuali per modello; si tiene la migliore.
  • Sample scaling: norm scala ogni campione alla norma unitaria prima del fit, così pochi campioni molto intensi non dominano (Murphy et al. 2013); i punteggi vengono poi riportati in unità Raman.
  • Convergence e Max iterations: 1e-6 basta per esplorare; il modello finale usa le sue.
  • Split-half validation (S4C6T3): inizializzazioni per ciascuna metà, colonne usate per bilanciare le metà (per l'Ombrone river, campaign), soglia della congruenza di Tucker (0,95) e seme della divisione.
  • Samples left out of the model: i campioni esclusi dal modello. Per l'Ombrone ci sono già i 6 dell'Orcia di maggio, siti 5 e 6. Put back selected li reinserisce.

Run exploratory models calcola ogni modello e la sua validazione split-half. Sull'Ombrone, 2–4 componenti con 3 inizializzazioni hanno richiesto circa 3,5 minuti; con le impostazioni del progetto (2–7 componenti, 10 inizializzazioni) servono decine di minuti.

Il modello finale

Nel riquadro Final model imposta numero di componenti, inizializzazioni (20), tolleranza (1e-8) e iterazioni massime, poi Fit final model. Il modello viene calcolato e validato di nuovo con lo split-half.

5 · Fiumi e date

Confronta campagne, siti e fiumi su qualsiasi variabile della tabella degli indici o del modello finale: indici, metriche CDOM, Fmax di ogni componente e la sua quota sul totale (C1_pct, …).

Le impostazioni

  • Variable: la variabile da confrontare.
  • Group, Time, Site: le colonne della tabella degli abbinamenti con fiume, campagna e sito (per l'Ombrone river, campaign, site).
  • Site table (facoltativa): CSV con le colonne di gruppo e sito più, per esempio, latitudine, longitudine e distance_km; Position along the river sceglie la colonna che ordina i siti lungo il fiume.
  • Covariate table (facoltativa): CSV con le colonne di gruppo e tempo, scritte esattamente come nei campioni (es. 2024-05), più per esempio portata e pioggia.
  • Le tabelle si uniscono ai campioni solo se i valori coincidono esattamente; le righe senza corrispondenza vengono segnalate.

Cosa calcola

  • Unità statistica. Le repliche di un sito in una data vengono mediate prima di ogni test, così non contano come campioni indipendenti (Hurlbert 1984). La tabella è in Site means.
  • Avviso fiume–stagione. Se due fiumi non sono mai stati campionati nella stessa data, le loro differenze non si distinguono da quelle tra date: l'avviso resta in alto, sopra i risultati. Sull'Ombrone compare sempre, perché il Farma è stato campionato in mesi diversi da Merse e Orcia.
  • Differenze tra campagne, dentro ogni fiume: Kruskal–Wallis e confronti a coppie di Dunn con correzione di Holm (vista Tests).
  • Lungo il fiume e con le covariate: correlazione di Spearman con la posizione dei siti e con le covariate (vista Correlations).
  • Composizione PARAFAC: la quota media di ogni componente per fiume e campagna (vista PARAFAC composition, dopo il modello finale).

Save to output folder scrive tabelle e figure in campaigns/<variabile>/ nella cartella di uscita, con un file di note che riporta il metodo e gli avvisi.

Colori degli EEM

Tutti i grafici degli EEM (anteprima delle correzioni, componenti PARAFAC, figure esportate) usano la stessa scala, scelta in View → EEM colours:

  • Cary Eclipse (violet, blue, green, yellow, red), quella predefinita: viola per i valori bassi, poi blu, verde, giallo e rosso per i valori alti, come nei grafici del software dello strumento.
  • Single-hue blue (perceptually ordered, for print): da bianco a blu scuro, la scala delle figure della Fase 6.

La scelta si salva nel progetto. La scala arcobaleno è comoda per confrontare con lo strumento, ma i salti di colore (per esempio tra verde e giallo) sembrano confini che nei dati non ci sono; per le figure da pubblicare conviene la scala blu (Crameri et al. 2020, Nature Communications 11, 5444).

Rifare tutto da script

Il file di progetto basta per ripetere l'analisi senza l'app:

from eemkit import pipeline

s = pipeline.load_settings("progetto.toml")
raw = pipeline.load(s, base="cartella/del/progetto")
after_raman = pipeline.correct_until_raman(raw, s, base="cartella/del/progetto")
corrected = pipeline.finish_corrections(after_raman, s)
indices = pipeline.compute_indices(after_raman, s)
indices = indices.join(pipeline.compute_absorbance(after_raman, s))
ds = pipeline.parafac_input(corrected, s)
exploration = pipeline.explore(ds, s)
model, split = pipeline.fit_final(ds, s)
pipeline.export_results("risultati", s, corrected=corrected, indices=indices,
                        exploration=exploration, model=model, split=split)
table = pipeline.sample_table(indices, model)
res = pipeline.campaign_analysis(table, "HIX", s, base="cartella/del/progetto")
pipeline.export_campaigns("risultati/campaigns/HIX", res, s)

Un parametro senza valore predefinito, come il cammino ottico, ferma l'esecuzione con un messaggio che lo nomina. base serve a trovare i file della correzione spettrale, se indicati con un percorso relativo al progetto.

Problemi comuni

Messaggio o situazioneCosa fare
«Enter both cuvette path lengths»Inserisci i due cammini ottici nel passo 2 (per l'Ombrone 1 cm).
«Spectral correction needs both the excitation and the emission file»Scegli anche l'altro file, oppure togli quello scelto con Clear.
«… factors cover … nm, grid needs … nm»Il file dei fattori non copre tutto l'intervallo degli EEM e ne serve uno che lo copra. Ritagliare non aiuta: la correzione spettrale si applica prima del ritaglio.

«Load the data first» / «Apply the corrections first»Manca un passo precedente: segui l'ordine dei passi.
Errore della tabella degli abbinamentiL'elenco indica riga e problema (file mancante, sample_id doppio, include non valido). Correggi e ricarica.
«… sample(s) have no blank / absorbance»Completa la tabella, oppure scegli drop in Samples without blank or absorbance.

«CDOM metrics: N sample(s) with values left empty»Normale con assorbanze basse: il motivo di ogni cella vuota è in cdom_notes. Per acque limpide serve una cuvetta più lunga.
Avviso «… were never sampled at the same …»Fiumi e date sono sovrapposti nel disegno di campionamento: confronta le date dentro ogni fiume, non i fiumi tra loro.
Il grafico degli indici non compareLa colonna scelta in grouped by ha più di 8 gruppi: scegline un'altra.
«The data folder is read only»Salva progetto, tabella o risultati fuori dalla cartella dei dati.

Limiti attuali

  • Legge solo i CSV «ASCII with log» del Cary Eclipse (EEM 3-D) e del Cary 60 (assorbanza).
  • Le date delle tabelle facoltative si abbinano solo se scritte esattamente come nei campioni.
  • eemkit non fornisce fattori di correzione spettrale: vanno misurati per il proprio strumento.
  • Annullare un calcolo ha effetto solo alla fine del modello in corso.
  • L'interfaccia è solo in inglese.
  • L'app non salva i risultati nel progetto: riaprendolo vanno ricalcolati, oppure si usano i file esportati.
